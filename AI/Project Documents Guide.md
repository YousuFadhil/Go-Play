\# Project Documents Guide



This repository contains the complete project documentation.



These documents are the official source of truth.



Do not replace or reinterpret them.



If documentation conflicts, stop and ask for clarification.



\---



\# Reading Order



Before starting any implementation, read the documents in the following order.



\## 1. PRD



Purpose:



Understand the product idea.



Contains:



\- Business goals

\- Target users

\- MVP scope

\- Functional requirements

\- Future phases



\---



\## 2. SRS



Purpose:



Understand the software requirements.



Contains:



\- Functional requirements

\- Non-functional requirements

\- System behavior

\- Business rules



\---



\## 3. UI / UX



Purpose:



Understand how the application should look and behave.



Contains:



\- Screen flow

\- Navigation

\- Components

\- User experience



\---



\## 4. Wireframes



Purpose:



Understand page layout.



Contains:



\- Screen hierarchy

\- Navigation

\- Page relationships



\---



\## 5. Workflow



Purpose:



Understand system processes.



Contains:



\- User journeys

\- Business workflows

\- Process logic



\---



\## 6. ERD



Purpose:



Understand entity relationships.



Contains:



\- Tables

\- Relationships

\- Keys



\---



\## 7. Database Design



Purpose:



Understand the physical database design.



Contains:



\- Schema

\- Constraints

\- Naming

\- Data structure



\---



\## 8. Technical Architecture



Purpose:



Understand the software architecture.



Contains:



\- Layers

\- Modules

\- Responsibilities

\- Technical decisions



\---



\## 9. Development Blueprint



Purpose:



Understand implementation priorities.



Contains:



\- Development phases

\- Milestones

\- Feature order



\---



\# Development Rules



When implementing a feature:



1\. Read only the documents relevant to that feature.

2\. Avoid reading unnecessary documents.

3\. Follow the approved documentation.

4\. Never change documentation without approval.



\---



\# Priority Order



When documents overlap, follow this priority:



1\. Latest approved decision from the Product Owner.

2\. PRD.

3\. SRS.

4\. Technical Architecture.

5\. Database Design.

6\. ERD.

7\. Workflow.

8\. UI / UX.

9\. Wireframes.



If two documents conflict, stop and ask.



\---



\# Important



Documentation is the project's memory.



Do not duplicate documentation.



Do not rewrite documentation.



Use documentation as the single source of truth.
